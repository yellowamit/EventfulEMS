# EventfulEMS - Deployment Guide

## Prerequisites

Before deploying to Render or any production environment, ensure you have:

1. **MongoDB Atlas Account** - Create a database and get your connection string
2. **Render Account** - Sign up at [render.com](https://render.com)
3. **Git Repository** - Push your code to GitHub

## Building Locally

Test the production build locally before deploying:

```bash
# Install all dependencies
npm run install:all

# Build the client for production
npm run build:client

# This should generate a `client/dist/` folder

# Verify the build output exists
ls client/dist/
```

## Environment Variables for Production

You need to set these variables in your Render deployment:

| Variable | Purpose | Example |
|----------|---------|---------|
| `NODE_ENV` | Set to production | `production` |
| `MONGO_URL` | MongoDB Atlas connection string | `mongodb+srv://user:pass@cluster.mongodb.net/dbname?retryWrites=true&w=majority` |
| `JWT_SECRET` | Secret for JWT tokens (auto-generated by Render) | Auto-generated |
| `MONGO_DB_NAME` | Database name | `eventfulems` |
| `CLIENT_ORIGIN` | Your production domain (auto-set by Render) | `https://yourapp.onrender.com` |
| `PORT` | Server port | `4000` |

## Deployment Steps on Render

### 1. Connect Your Repository
- Log in to [Render Dashboard](https://dashboard.render.com)
- Click "New +" → "Web Service"
- Connect your GitHub repository
- Choose the branch (usually `main`)

### 2. Configure the Service
- **Name**: `eventfulems`
- **Environment**: `Node`
- **Build Command**: `npm run build`
- **Start Command**: `npm start`
- **Plan**: Free tier (or paid if needed)

### 3. Add Environment Variables
In the "Environment" section, add:
- `NODE_ENV` = `production`
- `MONGO_DB_NAME` = `eventfulems`
- (Leave `MONGO_URL` and `JWT_SECRET` for next steps)

### 4. Add Secrets (from MongoDB Atlas)
1. Go to **MongoDB Atlas**
2. Create a new database user if you don't have one
3. Copy your connection string (format: `mongodb+srv://username:password@cluster.mongodb.net/eventfulems?retryWrites=true&w=majority`)
4. In Render dashboard:
   - Add `MONGO_URL` environment variable with your connection string
   - Make sure the database name matches your MONGO_DB_NAME

### 5. Set CLIENT_ORIGIN (Optional but Recommended)
After your app is deployed and has a URL:
- Get your Render URL (e.g., `https://eventfulems.onrender.com`)
- Add `CLIENT_ORIGIN` environment variable with this URL

### 6. Deploy
- Click "Create Web Service"
- Render will start the build process
- Monitor the logs in the "Logs" section
- Wait for "Your service is live!"

## Verifying Your Deployment

Once deployed, verify everything works:

```bash
# Check API health
curl https://yourapp.onrender.com/api/health

# Should return:
# {"status":"ok","environment":"production"}
```

Visit your app in the browser and test:
- [ ] User registration works
- [ ] User login works
- [ ] Can create events
- [ ] Can view events
- [ ] Can purchase tickets
- [ ] Images upload correctly

## Troubleshooting Deployment Issues

### Build Fails: "Cannot find module"
- Ensure `npm run install:all` works locally
- Check that `client/dist/` is created after `npm run build:client`
- Verify all dependencies are in `package.json` (not global installs)

### App Crashes After Deploy
Check the Render logs:
1. Click your service
2. Go to "Logs" tab
3. Look for MongoDB connection errors:
   - **"MONGO_URL is missing"** → Add MONGO_URL environment variable
   - **"Connection refused"** → Check MongoDB connection string is correct
   - **"Authentication failed"** → Verify MongoDB username/password are correct

### Images Not Loading
- Ensure `api/uploads/` directory exists and is writable
- Check that file paths in the API are correct
- On Render free tier, uploads are lost when the service restarts

### CORS Errors in Browser
- Set `CLIENT_ORIGIN` environment variable to your Render domain
- Or update `allowedOrigins` in `api/index.js` if needed

## Production Checklist

Before going live:

- [ ] MONGO_URL is set and connection works
- [ ] JWT_SECRET is configured (auto-generated is fine)
- [ ] CLIENT_ORIGIN matches your production domain
- [ ] NODE_ENV is set to "production"
- [ ] API health check passes (`/api/health`)
- [ ] User registration and login work
- [ ] Event creation works with image upload
- [ ] Ticket purchases work

## Performance Optimization Tips

1. **Enable Caching** in Render settings
2. **Use a Paid Plan** if you need better performance
3. **Optimize MongoDB Queries** - Add indexes to frequently queried fields
4. **Compress Images** before uploading
5. **Monitor Logs** for slow endpoints
